Conexión con el ERP sin conectar

Toda la aplicación pide los artículos a un solo objeto. Cambia el origen aquí, o directamente en la constante ORIGEN del código, y el resto sigue igual.

Rutas que tiene que servir el backend

GET  {base}/articulos?q=<texto>&limit=8   → [ {...}, {...} ]
GET  {base}/articulos/<referencia>        → { ... }

Forma de cada artículo

{
  "ref":   "500600",            // referencia del maestro   OBLIGATORIO
  "desc":  "PLUMERO EXTENSIBLE",// descripción              OBLIGATORIO
  "code":  "8436025811529",     // EAN-13 o GTIN-14         OBLIGATORIO
  "sym":   "ean13",             // ean13 | itf14 | code128  opcional
  "marca": "newmop",            //                          opcional
  "uds":   "12",                // unidades por caja        opcional
  "extra": "(INCLUYE ASA)"      // texto fijo del artículo  opcional
}

Si las columnas del ERP se llaman de otra forma, no hay que tocar nada más: se añaden los nombres reales a MAPA_CAMPOS y se traducen solos. Si el ERP no manda sym, se deduce por la longitud del código.

Lo que la plataforma nunca escribe

El ERP se consulta en solo lectura. La plantilla, el orden de los campos, el tamaño, el logo y la imagen viven en la plataforma enlazados por referencia. El lote y las copias son de cada impresión y no vuelven al maestro.
